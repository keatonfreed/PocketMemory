# Pocket Memory

An iPhone-first personal memory app. React/JavaScript runs inside Capacitor; Neon/Postgres and Vercel provide authenticated sync and AI orchestration.

Start with the [step-by-step Apple, Vercel, environment, database reset and Xcode guide](docs/setup.md).

## Development

Use Node 24 LTS (`nvm use`) and Xcode 26+. Install dependencies with `npm ci`. Copy the variable names from `.env.example` into ignored `.env.local` and fill in the values. `npm run check:config` reports presence only; it never prints secrets. No provider credentials belong in the native bundle. Only `VITE_API_URL` is public.

- `npm run dev` — frontend development. The web root is informational; Apple sign-in runs natively.
- `npm run lint`, `npm test`, `npm run build` — code checks (no browser automation).
- `npm run db:migrate` — Better Auth’s built-in Postgres migration, then the idempotent application migration. This changes the database named in `DATABASE_URL`; use a development Neon branch first.
- `npm run ios:sync` — builds local assets, syncs installed plugins with Capacitor, and configures the Xcode project.
- `npm run ios:open` — opens Xcode.
- `npm run ios:build` — unsigned simulator compilation; does not launch the app.

Deploy the existing repository to Vercel with its Vite build settings and the server environment variables. Set `BETTER_AUTH_URL` and `VITE_API_URL` to the same HTTPS deployment origin (without trailing `/api`). Rebuild/sync the iOS app after changing `VITE_API_URL`. A local frontend alone does not host the API; use Vercel's local runtime or the development deployment. The project does not load a remote website inside Capacitor.

## Sign-in and native setup

Sign in with Apple is the only provider. Better Auth manages accounts, database-backed rate limits, 90-day renewable sessions, and fresh-session account deletion. Capgo Social Login invokes Apple's native sheet and returns the one-time authorization code. The server exchanges it, Better Auth verifies the Apple token and nonce, and the session is saved using the secure-storage plugin (device-only Keychain). The plugin's temporary token cache is cleared after exchange.

Register `app.pocketmemory.ios` (or your own bundle ID) in Apple Developer with Sign in with Apple enabled. Put that same ID in `APPLE_BUNDLE_ID`, and add the Apple Team ID, Key ID, and P8 key to the **server** environment. `npm run ios:sync` applies the bundle ID, team if configured, and sign-in entitlement. Apple identifiers, credentials, signing membership, and App Store Connect records must belong to your account; they cannot be manufactured by the repository. No web Services ID or web OAuth callback is required for this native flow.

Native plugins: official Capacitor App, Keyboard, Network, Local Notifications, Filesystem, and Share; community SQLite; Aparajita secure storage; Capgo Social Login. Google/Facebook/Twitter implementations are disabled via the plugin's supported configuration. Swift Package Manager dependencies are generated by `cap sync`; no manual Pods cleanup.

`prepare-plugins.mjs` removes native diagnostic `print` statements from Capgo's Apple provider because the installed release prints identity payloads/tokens. It runs after install and before native sync. It also fixes an upstream SPM hook omission for the Google dependency so the Apple-only configuration is respected. It does not alter authentication behavior. `xcode`'s transitive UUID dependency is overridden to the compatible CommonJS 11.x line to avoid the older vulnerable version.

## Data and AI

See [architecture](docs/architecture.md). Original entries and replies are separate from interpreted knowledge. Every knowledge version has a source and revision. User edits clear the current AI-source link and preserve earlier versions. Memory deletion removes revisions; entry deletion removes the original but deliberately does not erase separately derived knowledge. Account deletion revokes Apple access and cascades through all app tables.

JEV (`jev-latest`) classifies intent and lifetime. OpenAI Responses uses `MEMORY_MODEL` for confident captures and `AGENT_MODEL` for assistance; both default to `gpt-4.1-mini` so this does not depend on a newly fine-tuned model. The old fine-tuning model's schema is incompatible with the new workflow. `QUERY_MEMORY_MODEL` and `ASK_MEMORY_MODEL` are no longer used. Models are server settings and can be changed independently.

AI keys are not needed to run tests/builds. Missing AI configuration preserves the original entry and shows a retryable failure; it never fabricates a response or silently substitutes a different service. No live provider calls or production database migrations are part of the test command.

The old `ai/` dataset editor remains as an **offline legacy development utility**. Its examples never enter the app. Old browser data is not imported, per the requested clean start. Existing web-push tables are not touched by the new migration; retire them separately if unused by older deployments.

## Before release

See [release notes and required checks](docs/release.md). A successful build is not Apple approval or proof of live-provider behavior.

The native welcome and Apple sign-in flow now includes explicit AI permission saved to the account. The website uses a separate public landing/support/policy layout. The microphone uses Capgo's native speech-recognition plugin (Apple speech service), with permissions requested on tap. Run `ios:sync` after pulling these UI/plugin changes; real dictation must be checked on iPhone.
